RUST RAID LOADOUTレイド装備プランナー（非公式）— 使い方と運用方法

このサイトでできること

Rust のレイドに参加する人ごとに「役割」を作り、手持ち（ホットバー6）・バッグ（インベントリ24）・装備（着用8）・バックパック（小型12／大型28）に入れるアイテムと数量を設定します。 レイド当日は「レイド表示」で大きく確認しながら準備でき、設定したアイテム一覧は 工業用コンベアのフィルターJSON としてコピーして、ゲーム内のコンベアにそのまま貼り付けられます。

1. 開き方

公開URL：https://8531050yseasound-ship-it.github.io/rust-raid-planner/
メンバーにはこのURL、または計画を含む「🔗 共有リンク」を送るだけで使えます（インストール・ログイン不要、スマホ可）。

ローカルで使う（自分のPC・開発用）

フォルダ rust-raid-planner の中で次を実行し、ブラウザで http://localhost:8741 を開きます。

注意：index.html をダブルクリック（file://）で開くとアイテム一覧（items.json）が読み込めません。必ず上のサーバ経由、または公開先のURLで開いてください。

公開の仕組み（管理者向け）

GitHub リポジトリ 8531050yseasound-ship-it/rust-raid-planner の main ブランチを GitHub Pages で配信しています（静的サイト・サーバ処理なし）。 ローカルのフォルダで編集したら git add -A && git commit -m "..." && git push で公開へ反映されます（ビルド1〜2分＋CDNキャッシュ最大10分。すぐ確認したいときは Ctrl+F5）。 メンバーには「共有リンク」（→7章）を送るだけで同じ計画を開けます。

2. 参加者・役割を作る

操作方法
役割を追加左パネル「＋ 追加」→ 役割名（例：爆破担当、ビルダー、前衛）を入力。個人名は不要です。色は左の色ボタンで変更
1スロットの上限（サーバー設定）編集エリア上部の「1スロットの上限」で ×1／×2／×3／×5／×10 または任意の倍率を選びます。×1 が公式サーバーのスタック数（5.56弾 128、木材 1000、C4 10 など）。倍率を下げると上限を超えた分は自動で切り詰めます。オンライン部屋では部屋の作成者だけが変更できます
グループ（状況別）左パネル上部の「グループ」の「＋」→ グループ名（例：レイド／防衛／ファーム）と、入れる参加者にチェック → 保存。グループの丸いボタンを押すと、参加者一覧・レイド表示のタブ・「グループ合計」（準備リスト／コンベア書出）がその参加者だけになります。「すべて」で解除、「✎」で編集・削除（参加者自体は消えません）。オンライン部屋では作った本人（またはマスター）だけが編集でき、全員が選べます。
グループを選ぶと編集エリアの上に「📦 グループのまとめ」が出て、参加者全員の持ち物を集計したアイテムごとの合計と誰がいくつ持つかが一覧になります（「📋 コピー」で文章として Discord 等に貼れます。見出しクリックで折りたたみ）
複製・並べ替え・削除編集エリア上部の「複製」「▲▼」「削除」。「全消去」はその人のアイテムだけを空にします
複数のレイド計画ヘッダーの「＋ 新規計画」で計画を増やし、左上のプルダウンで切り替え。計画名は隣の欄で変更

3. アイテムを入れる・数量・入れ替え

操作方法
入れる（ドラッグ）右上のアイテム一覧からアイコンをドラッグして、手持ち・バッグ・装備・バックパックのスロットへドロップ。一覧は検索窓とカテゴリボタンで絞り込めます
入れる（クリック・連続配置）アイテム一覧のアイコンをクリック（選択状態になり、置けるスロットが光る）→ スロットをクリックするたびに同じアイテムが入ります（何個でも連続）。終わるときは Esc、一覧の「終了」、または同じアイコンをもう一度クリック。Shiftを押しながらスロットをクリックすると1個だけ置いて終了
入れる（検索ダイアログ）空スロット + をクリック → 検索窓に入力 → クリックか Enter（先頭候補）。↑↓で候補移動、Escで閉じる
★レイド定番を自分好みにアイテム一覧や検索ダイアログの各アイコン右上の ☆ を押すと「★レイド定番」に追加、★ を押すと外せます。「↺ 既定に戻す」で初期の一覧に戻ります（設定はこのブラウザに保存されます）
検索できる言葉日本語名・通称・英語名・shortname のどれでも。例：C4 ロケラン HQM 注射器 ammo.rifle lr300。上部のカテゴリボタン（★レイド定番／武器／弾薬／医療…）で絞り込み
数量を変える入っているスロットをクリック → 数量欄を編集（Enterで確定）、−／＋、または「MAX」。1スロットに入る数はアイテムごとの上限（スタック数 × 倍率）までで、それ以上は入りません。弾薬・資源・医療品は上限いっぱいが初期値、武器や装備は1個です
装備テンプレ装備欄の見出しにある「装備テンプレ ▾」→ 名前を付けて「今の装備を保存」。次回からは一覧の「適用」で装備欄（着用7＋特別枠）を一式まとめて置き換えられます。「×」で削除。テンプレはこのブラウザに保存され、部屋の他の参加者には共有されません
装備枠のルール装備は着用7スロット（装備品カテゴリのみ）＋特別枠1（点線の8番目）。特別枠にはバックパック（小型／大型）とパラシュートだけ入ります。他の場所に入れようとすると案内が出ます
入れ替え・移動ドラッグ＆ドロップ（別の欄へも可）。ドラッグしたまま画面の上端・下端に近づけると自動でスクロールします。スマホは スロットをタップ →「移動」→ 移動先をタップ
削除右クリック、スロットをクリック →「削除」、またはスロットから右のアイテム一覧へドラッグして捨てる
元に戻す／やり直す右上の「↶」「↷」または Ctrl+Z／Ctrl+Y。アイテムの配置・数量・入れ替え・削除・参加者の追加や削除・役割名など、直近60手まで戻せます（オンライン部屋では自分の投稿だけ。ページを再読み込みすると履歴は消えます）
アイテムの詳細（拡大表示）右上の「🔍 拡大表示」をオンにすると、スロットやアイテム一覧にマウスを乗せたとき大きなアイコンと英語名・shortname を表示します（既定はオフ。設定はこのブラウザに保存）

3.5 スクショ／画面共有から取り込む

ゲーム内の持ち物を手入力せずに、インベントリ画面（Tab）のスクリーンショットから読み取って参加者に取り込めます。編集エリア上部の「📷 スクショ取込」から。

  1. 画像を渡す：「画像ファイルを選ぶ」／ダイアログへドロップ／Ctrl+V で貼り付け（PrtSc や Win+Shift+S の直後に貼り付けが便利）。「画面共有から取得」を押すと Rust のウィンドウを選んで、その場の画面を「📸 この画面を取り込む」で1枚取り込めます（Rust はフルスクリーンではなくボーダーレスウィンドウにしておくと選べます）
  2. 範囲を囲む：画像の上でドラッグして、まずバッグ 4×6 のマス目全体を囲みます。次に手持ち 1×6（「手持ちを自動推定」でも可）、必要なら装備（縦 7 または 8 段）。多少ずれていても、認識時に枠を自動で補正します
  3. 認識する：全アイテムのアイコンと照合して、マスごとの候補が並びます。黄色枠は自信が低いので確認してください。候補をクリックすると検索ダイアログで修正、右クリックで「空き」にできます
  4. 取り込む：「この内容を…取り込む（上書き）」で選択中の参加者のスロットを置き換え、「空きスロットだけ埋める」なら既存の中身は残します。装備枠のルール（着用7＋特別枠）は取り込み時にも適用されます
できないこと：数量（×128 などの数字）は画像から読み取りません。取り込み後は上限いっぱいなど既定の数量が入るので、必要に応じて直してください。バックパックの中身は現状の Rust の画面では別ウィンドウなので、開いた状態のスクショを「バッグ 4×6」として読み込むと、その分をバッグ欄に取り込めます（あとでドラッグで移動）。

4. バックパックを背負う／中身を設定する

装備の特別枠（8番目・点線）に小型／大型バックパックを入れると背負った状態になります。アイテム一覧からドラッグするか、「バックパック」欄のプルダウンで選んでも同じです（パラシュートを入れると中身は使えません）。

選択中身のスロット準備リスト・コンベアへの反映
背負わない表示されない含まれない
小型バックパック12中身 ＋ 小型バックパック本体×1
大型バックパック28中身 ＋ 大型バックパック本体×1
ヒント：大型→小型に切り替えると13スロット目以降は隠れますが、データは消えません（「容量外に n 件あり」と表示）。大型に戻せば再表示されます。 コンベア書出で中身を除外したいときは「バックパック（本体＋中身）も含める」のチェックを外します。

5. レイド当日の使い方

  1. 右上の「⚔ レイド表示」を押す → 編集UIが消え、大きなアイコン＋数量＋日本語名の一覧になります（スマホでも横スクロールなし）
  2. 上のタブで参加者を切り替え、各自が自分の役割のアイテムを箱から取り出す
  3. 下の「準備リスト」はアイテム種類ごとの合計数。取り出したらチェックを入れる（チェックは端末ごとに保存、「✓ リセット」で全解除）
  4. 「全員合計」タブで、レイド全体で必要な数（ロケット合計など）を確認
  5. 「✎ 編集に戻る」で通常画面へ

6. 工業用コンベアへ貼り付ける

  1. 右下「工業用コンベア フィルター書出」で対象を選ぶ（「この人」タブ＝選択中の参加者、「全員合計」タブ＝全員分）
  2. 「📋 コピー」を押す（クリップボードにJSONが入る。「JSON」ボタンで中身を確認可）
  3. ゲーム内で工業用コンベアを開き、フィルター画面の Paste（貼り付け）ボタンを押す
  4. Apply で確定
オプション意味
数量を Max（出力上限）に反映ON：各アイテムの MaxAmountInOutput に数量が入り、「出力側の箱にその数だけ移して止まる」動作。OFF：0（上限なし）
1台あたり N 件1台のコンベアに入るフィルターは 12 件（版によって 16 件）。超える分は自動で「コンベア 1/2/3…」に分割されるので、台数分コピー→貼り付けを繰り返す
装備も含める／バックパックも含める着用品・バックパック（本体と中身）をフィルターに含めるか

書き出される形式はゲーム内の「Copy(JSON)」と同じ構造です：

[
  {
    "TargetCategory": null,
    "MaxAmountInOutput": 8,
    "BufferAmount": 0,
    "MinAmountInInput": 0,
    "IsBlueprint": false,
    "BufferTransferRemaining": 0,
    "TargetItemName": "ammo.rocket.basic"
  },
  ...
]
使い方の例：レイド前に「準備箱」を作り、共用倉庫→コンベア→準備箱と配管。各役割のJSONを貼ったコンベアを動かすと、必要な数だけが準備箱に自動で集まります。

7. メンバーへの共有・バックアップ

🌐 オンライン部屋（みんなで同時編集・おすすめ）

使い方：管理者が「🌐 オンライン部屋を作る」→ 表示されたURL（…/?room=xxxxxxxxxx）をメンバーに送るだけ。 受け取った人はURLを開くだけで参加でき、パスワードもログインも不要です。
できること説明
自分の投稿「＋ 追加」で作った役割は自分の投稿（左の一覧に「自分」バッジ）。編集した内容は自動保存され、部屋を開いている全員の画面に数秒以内に反映されます
他の人の投稿「閲覧」バッジ。見ることはできますが編集はできません。「コピーして自分用に編集」を押すと、同じ中身の自分の投稿ができて自由に編集できます
全員合計・コンベア準備リストの「全員合計」と、コンベア書出の全員分は、部屋にいる全員の投稿を合計します
部屋の名前・上限倍率部屋を作った人（またはマスター）だけが変更できます
編集権限を渡す部屋の作成者（またはマスター）は部屋バーの「👥 編集権限」から、部屋に参加している人にチェックを付けてすべての投稿・グループを編集できる権限を渡せます（外すのも同じ場所）。まだ投稿していない相手には、相手が「🪪 自分のID」でコピーした ID を送ってもらい「IDで追加」。権限をもらった人は部屋バーに「✎ 編集権限あり」と出ます。Google でログインしている相手に渡すと、その人はどの端末でも同じ権限で使えます（匿名の相手はその端末だけ）
マスターアカウント管理者の Google アカウント（ちゃいる）でログインすると「★マスター」となり、部屋内のすべての投稿・グループ・部屋設定を編集・削除できます（サーバー側のルールでも許可済み）。マスターの追加・変更は firebase-config.js の RRP_MASTERS と Firestore ルールの isMaster() の UID を両方直します
退出「退出（ローカルへ）」で自分のPC内の計画に戻ります（部屋のデータは消えません。URLを開けばまた参加できます）
「自分」の判定：何もしなくてもブラウザごとの匿名IDで判定されます（入力不要）。 別の端末やスマホでも自分の投稿を編集したい人は、右上の「Googleでログイン」を押してください（無料・Googleアカウントの名前とメールアドレスだけを使います）。 匿名で作った投稿はログイン後もそのまま自分のものとして引き継がれ、以後はどの端末でも同じ本人として扱われます。他の人には投稿の作成者名（Googleの表示名）が見えます。
注意： ①ログインせずに別の端末・別のブラウザで開くと、自分の投稿が「閲覧」扱いになります（「コピーして自分用に編集」で引き継げます）。 ②すでに別の端末で同じGoogleアカウントを使っている場合、この端末で「Googleでログイン」するとそのアカウントに切り替わり、この端末で匿名のまま作った投稿は「閲覧」扱いになります（確認ダイアログが出ます）。 ③ログインのポップアップがブロックされる環境では、ブラウザのポップアップを許可してください。

スナップショット共有（サーバなし）

方法説明
🔗 共有リンク計画全体を圧縮してURLに埋め込みます（サーバ保存なし）。Discord等で送れば、受け取った人はそのURLを開くだけで「新しい計画」として取り込まれます。あとで編集しても相手側には反映されないので、更新したら再度リンクを送ってください
💾 書出計画をJSONテキストで表示 → コピーしてメモ等に保存（バックアップ用）
📂 読込書出したJSON、または共有リンクのURLを貼り付けて取り込み
データの保存場所：計画はブラウザの localStorage に保存されます（PC・ブラウザごとに別。同じPCでも別ブラウザには引き継がれません）。ブラウザのサイトデータを消すと消えるので、大事な計画は「書出」でバックアップしてください。

8. 運用（管理者向け）

オンライン部屋の初期設定（1回だけ・Firebase 無料枠）

設定済み（2026-09-07）：Firebase プロジェクト rust-d3d5e（Firestore 東京リージョン・匿名ログイン有効・Googleログイン有効・承認済みドメインに公開サイト追加済み・所有者ルール公開済み）。以下は再設定や別プロジェクトへ移すときの手順です。コンソール：console.firebase.google.com/project/rust-d3d5e

同時編集は Google の Firebase（Firestore）を使います。設定は3ステップです。

  1. firebaseConfig を貼る：Firebase コンソール → ⚙ プロジェクトの設定 → 「マイアプリ」→ SDK の設定と構成 に出る firebaseConfig = { apiKey: "...", projectId: "...", ... } の中身を、リポジトリの firebase-config.js に貼る： 
    window.FIREBASE_CONFIG = {
  apiKey: "AIza...",
  authDomain: "xxxx.firebaseapp.com",
  projectId: "xxxx",
  storageBucket: "xxxx.appspot.com",
  messagingSenderId: "...",
  appId: "..."
};
    （Life Planner の設定画面「ふたりで同期」に貼った構成と同じもの。Web用APIキーは公開しても問題ない種類で、保護はルールで行います）
  2. 匿名ログインを有効化：Firebase コンソール → Authentication → Sign-in method → 「匿名」を有効にする。これで利用者は何も入力せずに「自分」を識別できます。30日自動クリーンアップはオフのまま（オンにすると匿名ユーザーの投稿の所有権が消えます）
  3. Googleログインを有効化（任意）：同じ画面で「Google」を有効にし、公開名とサポートメールを設定。さらに Authentication → 設定 → 承認済みドメイン に公開サイトのドメイン（8531050yseasound-ship-it.github.io）を追加
  4. Firestore ルールを貼る：Firestore Database → ルール に、既存のルールの match /databases/{database}/documents { の内側へ次を追加して「公開」： 
    match /rustraid_rooms/{room} {
  allow read: if true;
  allow create: if request.auth != null && request.resource.data.createdBy == request.auth.uid;
  allow update: if request.auth != null && resource.data.createdBy == request.auth.uid;
  allow delete: if request.auth != null && resource.data.createdBy == request.auth.uid;
  match /members/{member} {
    allow read: if true;
    allow create: if request.auth != null && request.resource.data.uid == request.auth.uid;
    allow update: if request.auth != null && resource.data.uid == request.auth.uid && request.resource.data.uid == request.auth.uid;
    allow delete: if request.auth != null && resource.data.uid == request.auth.uid;
  }
}
    このルールで「誰でも閲覧・自分の投稿だけ書き換え可」がサーバ側でも保証されます（UIだけの制限ではなくなります）。

firebase-config.js を git push すると、公開サイトに「🌐 オンライン部屋を作る」ボタンが現れます。設定前はボタンが出ず、ローカル＋共有リンクだけで動きます。

データの置き場所：Firestore の rustraid_rooms/{部屋ID}（名前・作成者）と rustraid_rooms/{部屋ID}/members/{投稿ID}（各投稿。uid＝作成者の匿名ID）。無料枠（1日 読み取り5万・書き込み2万）で十分です。部屋を丸ごと消したいときは Firestore コンソールでその部屋のドキュメントを削除します。

日本語名を増やす

tools/jp_aliases.json に "shortname": ["表示名", "別名1", "別名2"] を追加し、後述の finalize（手順4）だけを再実行します。先頭が画面の表示名、以降は検索用の別名です。

月次更新（フォースワイプ後に新アイテムが増えたとき）

  1. 公式Wikiの Items_Overview と rusthelp の item-list のHTMLを保存（ブラウザで「名前を付けて保存」）
  2. node tools/build_items.js <wiki.html> <rusthelp.html> tools/items_raw.json tools/shortnames_extra.txt
  3. node tools/fetch_icons.js tools/items_raw.json（公式CDN files.facepunch.com/rust/item/{shortname}_{64|256}.png から新規分だけ取得）
  4. node tools/finalize_items.js tools/items_raw.json <items_text.md> tools/jp_aliases.json items.json（items_text.md はカテゴリ補完用の rostov114/rust-items の表）
  5. 更新した items.json と icons/ を公開先へアップロード
Node.js について：このPCでは C:\Program Files\nodejs\node.exe。Git Bash から使う場合は export PATH="/c/Program Files/nodejs:$PATH" を先に実行。

公開先の目安

  • 合計サイズ：約75MB（大半が256pxアイコン）。GitHub Pages（1GB上限）で問題なし
  • キャッシュ：アイコンとitems.jsonは長めのキャッシュ設定で構いません。index.html を更新したら再読み込み（Ctrl+F5）を案内
  • アクセス解析や広告を載せる場合は 権利表記 の条件を確認

9. 困ったとき

症状対処
「items.json を読み込めませんでした」file:// で開いている。node server.js 経由か公開URLで開く
検索してもアイテムが出ない英語名か shortname で試す（例：Timed Explosive Charge / explosive.timed）。日本語未登録なら jp_aliases.json に追加
ゲーム内で Paste しても反映されないクリップボードにJSONが入っているか「JSON」ボタンで確認 → もう一度コピー。1台の上限（12件）を超えていないか、「1台あたり」の設定を確認。Apply を押し忘れていないか
アイコンが表示されないアイテムがある公式CDNにアイコンが無い一部アイテム（廃止品・季節物など約180件）は台帳から除外しています
他のPC/スマホで計画が出ない保存はブラウザごと。共有リンクか「書出→読込」で移す
コピーが効かないhttpsでない環境ではクリップボードAPIが制限されることがあります。「JSON」ボタンでテキストを表示し、手動で全選択→コピー
